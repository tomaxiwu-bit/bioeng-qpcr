# qPCR 实验工作台：设计与实现

## 方案评估

采用“实验工作台 + 有依赖的分步工作流”，保留现有计算引擎和独立分析入口。
原来的 Validate / Analyze / Curves 适合已有导出文件的单次分析，但它们没有共同的
实验设计、板位、程序、运行快照和结果版本，用户需要重复录入信息，难以追踪结果
对应哪一次实验。新工作台把这些上下文保存在一个实验项目中。

不采用任意拖拽的通用 DAG 编辑器：qPCR 的主要依赖比较固定，任意连接会允许
“没有采集数据就定量”等无效路径。使用可点击节点、明确依赖、完成状态和下游失效
机制，既能回看任一步，也能保证实验顺序。

沿用 Python、dataclasses、NumPy / SciPy、Flask、原生 HTML / CSS / JavaScript；
SQLite 使用 Python 标准库，不增加前端框架、数据库服务或工作流引擎。

## 页面与模块

综合入口 `/lab` 展示五个主要定量研究模块；qPCR 的专业流程位于 `/workbench`。
酶动力学、发酵与 FBA 均可在浏览器分析、存档和恢复，也保留独立桌面面板。
文件预览与旧版对接/序列工具移入辅助兼容入口，历史记录不受影响。
通过 Windows 程序启动时，首页的桌面模块按钮经受限 API 和 Qt 队列信号切换页面；
独立 Web 服务也可运行浏览器分析；桌面切换功能需要由 Windows 程序启动。

qPCR 顶部为实验选择、新建、保存状态和公开示例，以及返回全部模块的入口。左侧步骤导航，
中央是当前步骤，右侧是项目摘要、来源与运行状态。旧 `/` 与 `/workspace` 保留链接。

| 步骤 | 输入与操作 | 交付给下一步的数据 |
|---|---|---|
| 样品与引物/探针 | 样品类型、分组、标准量与单位；引物序列、探针、染料/通道、内参标记 | 有稳定 ID 的样品和检测项目 |
| 配液与板位 | 96/384 孔板、每孔样品/检测项目；反应体积、组分体积、余量 | 板位和配液清单 |
| 上机程序 | 温度、保持时间、循环次数、采集步骤、通道、熔解扫描范围 | 可校验和导出的程序 |
| 运行与采集 | 确认运行；公开数据回放或真实 CSV/RDML 导入 | 不可变设计快照、原始文件哈希、逐孔测量 |
| Ct 与熔解曲线 | 仪器 Ct 或基线校正阈值法；熔解曲线平滑与 -dF/dT 峰 | 逐孔 Ct、Tm、峰与算法参数 |
| 质控 | 阴阳性对照、重复孔 SD、缺失孔、熔解证据；可配置实验室阈值 | PASS/WARN/FAIL/NOT_ASSESSABLE 和逐项证据 |
| 定量 | 选择目标、内参、校准样品；ΔΔCt 或标准曲线 | 逐样品结果、拟合参数、外推和缺失告警 |
| 报告 | 审阅结果与来源，生成 CSV / JSON / HTML | 可下载报告、原始证据、配置与审计记录 |

## 数据模型

`Project` 聚合 `SampleRecord[]`、`AssayRecord[]`、`PlateAssignment[]`、
`ReactionRecipe`、`InstrumentProgram`、`QCPolicy`、`AnalysisSettings`。
每次 `RunRecord` 冻结样品、检测项目、板位、配液、程序、设计摘要及采集数据；
测量使用 `(well, assay_id)` 键，允许同一物理孔不同荧光通道，禁止同孔同检测项目重复。
`Measurement` 保存仪器 Ct、原始扩增点、原始熔解点及来源；缺失值保持 null。

工作流结果与输入分离：`curves`、`qc`、`analysis`、`report` 是带配置与版本的衍生结果。
`revision` 在 SQLite 事务中用于乐观并发检查，避免两个浏览器覆盖彼此修改。
保存到本地 SQLite，刷新或重启不丢失；项目 JSON 是可迁移的完整备份。
每次曲线计算、质控、定量和报告生成均追加 `RunRecord.analysis_versions`，
包含时间、项目版本、完整输出，以及软件/科学依赖版本、Python 环境、输入摘要与参数。
便携版还记录构建时的源码摘要、Git 基线及工作区是否有未提交修改。
重新计算不删除旧分析版本；旧记录缺少的版本信息不使用当前环境补写。

## 数据传递和状态

```mermaid
flowchart LR
  S[样品 / 引物 / 探针] --> D[配液 / 板位]
  D --> P[温度循环 / 通道]
  P --> R[运行快照 / 采集文件]
  R --> C[Ct / 熔解曲线]
  C --> Q[质控证据]
  Q --> A[相对 / 绝对定量]
  A --> E[导出 / 报告]
```

节点状态为 `pending → ready → complete`；上游修改使已完成下游成为 `stale`。
缺少必要前置数据时拒绝推进。质控发现硬失败时标为 `blocked`，仍可导出问题报告，
但不会生成可发布的定量结论。WARN / NOT_ASSESSABLE 保留在定量结果和报告中。

设计修改后开启新的运行，旧 `RunRecord` 保留；分析参数或质控阈值修改不覆盖原始数据，
只使相应结果失效。真实文件按孔位和检测项目严格匹配当前设计，拒绝静默重分配。

## 科学与设备边界

- 运行状态明确区分“等待文件”“公开数据回放”“已采集文件导入”。没有厂商 SDK 时，
  不宣称能控制热循环仪或实时读取硬件。设备接入替换点在采集适配模块。
- Ct 默认保留仪器值；阈值法需要显式阈值和基线范围，不能把 sigmoid 拐点叫作阈值 Ct。
- 熔解峰使用原始温度/荧光数据计算，先按温度排序并合并重复温度。未提供熔解曲线时
  显示无法评估，不根据 Ct 伪造曲线。探针化学的熔解分析可标记不适用。
- NTC 无统一 Ct 界限；界限与阳性范围、重复孔 SD、峰显著性属于可编辑 SOP 配置。
- ΔΔCt 的效率假设必须显式确认；技术重复先汇总，不能当作独立生物学重复。
- 标准曲线使用相同检测项目和相同单位的已知正标准量拟合；未知量单位沿用标准，
  外推单独标记，不把相对稀释度伪装成绝对拷贝数。

## 演示来源和替换真实数据

演示数据、上游版本、SHA-256、许可和提取过程记录在
`web/examples/qpcr_workbench/` 与 `scripts/prepare_workbench_examples.py`。
上机程序或配液中上游未提供的信息明确标为教学配置，不代表原实验的执行记录。
真实数据可通过运行页上传，格式和替换入口会在界面与采集模块内同时注明。

## 使用与 API

Web：`python -m bioeng_qpcr.web`，访问 `http://127.0.0.1:8008/workbench`。
桌面：`bioeng-qpcr-gui` → 默认“综合实验工作台” → “打开综合实验工作台” → qPCR。
本地服务不会自动连接真实设备，不需要前端构建或额外数据库服务。

默认 SQLite 位于 Windows `%LOCALAPPDATA%/bioeng-qpcr/workbench.sqlite3`，
其他系统为 `~/bioeng-qpcr/workbench.sqlite3`。环境变量
`BIOENG_QPCR_WORKBENCH_DB` 可覆盖，测试使用 Flask `WORKBENCH_DB` 配置。

| API | 行为 |
|---|---|
| `GET /api/qpcr/projects` | 列出本地项目与公开示例选项 |
| `POST /api/qpcr/projects/import` | 从项目 JSON 备份恢复为新项目，不覆盖现有项目 |
| `GET /api/qpcr/templates` | 五套实验规划模板与六套图表/报告主题 |
| `POST /api/qpcr/projects` | 新建空项目或指定 `demo` 的示例 |
| `GET/PATCH /api/qpcr/projects/{id}` | 读取项目 / 携带 `revision` 保存指定设计字段 |
| `POST .../{id}/steps/{step}` | 校验依赖后推进或重新计算 |
| `POST .../{id}/replay` | 回放该示例的真实公开观测 |
| `POST .../{id}/acquire` | multipart 上传真实 CSV/RDML 与 `revision` |
| `POST .../{id}/new-run` | 保留旧数据，基于当前设计创建新运行 |
| `GET .../{id}/export/{kind}` | 项目、板位、程序、原始采集、定量或报告 |
| `GET .../{id}/figures/{kind}.{fmt}` | 下载当前主题的 SVG、PDF 或 300 dpi PNG |

导出类型：`project.json`、`plate.csv`、`protocol.json`、`acquisition.csv`、
`results.csv`、`report.html`。HTML 内嵌 Matplotlib SVG 图，可离线打开并打印。
JSON 可用于归档和迁移；项目列表提供备份导入入口。导入创建新项目，
保留历史分析并标记来自备份，重新计算当前曲线与质控，定量假设需要再次确认。

公开 Ct 示例的期望 kidney/brain 表达倍数为 5.6372830205680815。
RDML 子集的标准量单位原样保留 `cop`，不擅自解释成每反应或每微升。
来源文件未提供的阴阳性对照与元数据会以 `NOT_ASSESSABLE` / `WARN` 保留。

## 模板库与图表设计

实验规划模板：基因表达（48 孔）、绝对定量（27 孔）、染料法熔解验证（15 孔）、
双通道多重探针（24 个物理孔 / 48 条检测分配）、含无逆转录的对照检查（30 孔）。
模板只预填设计，没有原始观测。引物/探针序列保持空白；标准量、配液和程序明确为
需替换的教学配置。通过 `POST /api/qpcr/projects` 的 `template` 字段选择模板，
不能与公开数据 `demo` 同时使用。

图表与报告主题：期刊简洁、实验室汇报、色盲友好、黑白印刷、深色展示、柔和配色。
颜色、线型、字体、网格、坐标与图例统一控制。色盲/灰阶展示辅以线型和点形，避免
单独依赖颜色。相对定量有棒棒糖、水平柱状和点图三种布局，均明确为点估计，
不从技术重复伪造生物学误差条。标准曲线增加真实残差面板。

`Project.presentation` 保存 `theme`、`curve_scope`（选中孔、技术重复或全部孔）、
`relative_chart`。修改样式仅使报告版本失效，不清除 Ct、质控和定量结果。
浏览器预览与 Matplotlib 导出使用相同主题配置；报告内嵌同一图表导出器生成的 SVG。
图表类型为 `amplification`、`melting`、`relative`、`standard`；前两者可通过
`well` / `assay` 查询参数指定观测，错误孔位明确拒绝，不自动展示另一条曲线。
