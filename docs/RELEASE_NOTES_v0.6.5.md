# 0.6.5：统一历史与多实验分析工作台

八个模块继续保留，技术栈沿用 Flask、现有 Python 科学计算层与 PySide6。
新增浏览器入口不替换科学算法，也不删除原桌面页面。

## 三个模块接入统一存档

- 酶动力学：Michaelis–Menten 零抑制对照拟合、五模型全局抑制比较、SE、机制未决提示与残差。
- 发酵：Monod 参数和 95% 置信区间、Fisher 参数可辨识性、参数相关性、观测 / 拟合 / 残差全量表。
- FBA：上传 SBML / COBRA JSON，设置目标和方向，检查阻塞反应、死端代谢物。

成功完成的浏览器分析，复用 `analysis_records` 表自动保存原始文件及 SHA-256、
参数和完整结果。新接口记录实际采用的默认参数，避免恢复时依赖未来版本的默认值。
结果可导出全量 CSV、完整 JSON 备份与 SVG / PDF / 300 dpi PNG。
页面最多显示每张表的前 200 行，CSV 和 JSON 保留全部数据。

`/history` 汇总各浏览器模块记录，支持模块筛选、文件名搜索、恢复与下载备份。
每个筛选范围读取最近 100 条。qPCR 的实验、运行快照及项目备份仍在 `/workbench` 中管理，
统一历史页提供直接入口，不将有状态实验项目转换为一次性分析记录。

原桌面页增加统一工作台按钮。**原桌面页的独立计算不自动归档**；需要保存历史时，
从新浏览器入口运行。这样避免维护两套存档与恢复逻辑。

## FBA 情景比较

在原模型上计算基线，再在本次请求加载的模型实例上应用明确的反应边界修改，
比较目标函数和所有反应通量，分别显示基线与情景图。不修改上传的原文件。
约束格式为 `reaction_id,lower,upper`，多条以分号分隔，最多 20 条；
反应必须存在、不重复，边界须有限且下界不高于上界。

教程模型可用 `EX_o2_e,0,1000` 关闭氧摄入。该 ID 不会自动用于其他模型。
通量与目标值的单位沿用模型；FBA 可能存在替代最优解，不能将单次通量差解释为唯一的生物学响应。
无法求得最优解时保留求解状态与质量检查，不能以 0 替代缺失结果或推断成功。
CSV 逐行保留基线 / 情景求解状态；无最优解时，相应通量及差值留空。
浏览器通量图标明使用模型单位，避免为任意上传模型假定固定的通量单位。

## 示例与数据流

酶和发酵示例沿用原项目教学 CSV，界面标明并非实测。
FBA 使用 COBRApy 0.31.1 随包公开 E. coli core 教程模型，包含来源、上游许可链接及哈希。
来源和真实数据替换位置见 `src/bioeng_qpcr/web/examples/KINETICS_SOURCES.md`。
真实数据从对应模块上传，不覆写演示文件。

状态流转：选择模块 → 上传 / 示例就绪 → 设置参数 → 运行 → 审阅 → 自动存档。
修改输入或参数会清除当前结果显示；重新运行产生新记录，旧记录保持不变。
从本机历史恢复可直接审阅当时结果；外部备份恢复为新记录，历史结果保留供下载，
在本机复算前不展示为当前结论，也不提供可信结果 CSV。
无法写盘时保留已计算结果，并明确提示尚未保存。

## 当前边界

浏览器分析是同步请求，未增加后台任务队列或批次培养 / 多模型批量调度。
酶限 5000 行、24 个抑制剂浓度；Monod 限 500 个时间点；
FBA 限 2000 个反应和 3000 个代谢物，阻塞检查限 300 个反应并使用单进程。
更大的模型可继续使用桌面页。上传与备份导入维持 64 MiB 限制。
Monod 仍是批次培养模型，未新增补料、菌体死亡、产物抑制等模型。
未新增真实仪器联机、云同步或 GitHub 发布。
