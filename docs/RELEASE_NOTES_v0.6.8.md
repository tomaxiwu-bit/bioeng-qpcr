# 0.6.8：宣传前可靠性修复与首次使用指引

本版延续 0.6.7 的五个主要研究模块，修复结果解释与本地网页访问的边界问题。

- 共用 qPCR 汇总逻辑拒绝把部分未检出的重复孔直接取均值；批量分析明确记录样品排除和孔位，
  内参矩阵也保留不完整样品的排除。旧版独立入口与实验工作台的完整性要求一致。
- REP-001 更新为 1.1.0，证据记录总孔数、检出数和未检出数；缺失重复不会再显示为无警告的 PASS。
  检出孔之间已违反一致性阈值时仍判 FAIL；没有足够检出孔时保持无法评估。
  NTC 由独立的阴性对照规则评估，预期的未检出不作为普通样品缺失重复。
- 组间比较拒绝相同的处理组和对照组。
- 使用 Flask 3.1 的受信任 Host 校验，仅接受本机回环地址/域名；所有修改/分析请求统一检查浏览器 Origin。
  合并原先散落在各模块的重复检查。此工作台仍按本地单人使用设计。
- 首页增加 Windows 下载入口、实际桌面截图、五分钟公开示例和离线报告样例；保留原始许可和证据缺口。
- 补充科学边界、访问限制和跨入口回归用例；本地验证与远端 CI 状态分别记录。
- 修复公开 CI 的 Qt 导入失败：Linux 测试环境显式安装缺失的 EGL / OpenGL 运行库，
  统一使用 offscreen 后端，并保存测试报告和安装包构建产物。
- 跨平台回归补修效价数值边界：零宽相对效价区间保留原始点估计；模型适合性诊断
  不把浮点舍入残差的排序当作系统偏差。数值容差随响应尺度计算并进入证据，真实残差趋势仍会告警。
  文件拖放测试改用自建临时输入，不依赖开发者本地数据文件。

## 升级和结果差异

无需迁移数据库，不覆盖已有项目或历史结果。建议先导出 JSON 或关闭程序后备份数据库。
旧结果仍保留原先运行环境；重新计算时，原本被静默忽略的未检出重复可能使样品变成明确排除。
这是完整性要求收紧，不应通过把未检出填成 0 或最大 Ct 来恢复旧结果。

从源码升级网页功能时，请同步更新依赖：`python -m pip install ".[web,fba]"`。
Windows 用户应完整替换程序文件夹，保留数据库备份，不要混用新旧 `_internal`。

## 验证与适用范围

测试、包自检和公开数据基准用于验证软件行为，不代表所有实验条件均有科学有效性保证。
0.6.7 的历史公开基准保持原日期和版本；0.6.8 的基准在其独立目录保存。
真实仪器控制、独立实验室使用证据和临床验证没有在本版新增。
