# JOSS 准备情况

本文件是作者侧的准备清单，不是 JOSS 编辑或审稿人的正式结论。
工程收尾不能替代研究使用与公开维护证据。

## 0.6.7 已补

* 运行版本与环境、输入摘要、参数、不可变历史、旧备份兼容。
* 原始代码 MIT 许可、第三方许可清单及本地便携版对应源码材料。
* CONTRIBUTING、支持/问题反馈渠道、软件引用元数据、项目链接。
* 锁文件随源码分发，固定环境 CI 路径、独立安装包检查与科学自检。
* 公共基准记录环境，区分筛选后成功率和参考置信区间命中率。

CI 配置已更新不代表远端流水线已执行。本次仅本地发布；0.6.7 未作为 GitHub
公开版本或 DOI 归档。引用元数据中的 contributors 是软件贡献者集合，不能
替代论文的真实作者、机构或贡献声明。

## 仍须研究者补充

1. 实际研究案例：研究问题、使用者/课题组、使用时间和版本、脱敏输入与结果、
   本软件在研究中完成了什么、与参考结果的对照及使用反馈。不能把公开演示写成
   本项目已有独立用户，也不能把数据下载或测试通过写成研究成果。
2. 持续公开开发记录：目前本地 Git 可见最早提交为 2026-09-03，不能单独证明
   已满足超过六个月公开活跃开发的要求。如有更早公开仓库、发布、问题讨论或
   迁移历史，应提供原链接和日期；不要补造或回填历史。
3. 投稿稿件：Summary、Statement of need、State of the field、Software design、
   Research impact statement、AI usage disclosure，及真实作者/机构、文献、
   资助与利益冲突。重点解释为何建立此工作台，而不是贡献给现有工具。
4. AI 使用范围及人工核验：列明实际使用的工具/模型和可确认的版本、辅助环节、
   人工检查与关键研究决定。不能替人声明未进行的核验。正式评审沟通须遵守
   期刊的 AI 使用限制。

研究叙述以有证据的 qPCR 可追溯工作流为主，其余五个主要模块中的配套工具
按实际验证范围说明。算法原创并非唯一价值；跨入口结果一致、证据追踪和
公开可复现用例也需要具体证据。不要用模块数量代替研究贡献。

投稿前重新核对 [submission requirements](https://joss.readthedocs.io/en/latest/submitting.html)、
[paper requirements](https://joss.readthedocs.io/en/latest/paper.html) 和
[review criteria](https://joss.readthedocs.io/en/latest/review_criteria.html)。
最终带标签发布与长期归档按期刊评审流程完成，不因当前未有 DOI 就单独判为不合格。
