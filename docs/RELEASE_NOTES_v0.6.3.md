# 0.6.3：第一批可靠性改进

## 已完成

- 浏览器中的表格预览、图片预览、效价、对接和测序分析，成功后自动保存原始文件、
  参数和完整响应，写入现有本机 SQLite 的 `analysis_records` 表。
- 页面内切换模块保留草稿与结果；刷新或重启程序后可通过“本地分析记录”恢复。
- 支持下载记录备份和完整结果 JSON；复制结果不再截断为 20 万字符。
- 导入记录备份创建新记录，校验原始文件 SHA-256，并标记历史结果未经复算。
  恢复原始文件与参数后，可以重新分析；不会将外部历史响应直接渲染为可信图表。
- qPCR 支持恢复项目 JSON：新建项目、校验设计快照及测量记录、保存历史运行，
  对当前运行重新计算曲线与质控。旧定量结果不作为当前结论，效率假设需重新确认。
- 酶动力学缺少零抑制剂对照且存在多个浓度时，阻止合并拟合。
  非零极低浓度不再被近似认作零；单浓度拟合标注为表观参数。
- 浏览器、桌面和 CLI 的对接评分解释统一，明确其经验排序用途和证据边界。

## 使用与边界

所有八个科学与数据入口保留。桌面的酶、发酵和 FBA 暂未接入统一分析历史；
本轮新增持久记录覆盖上述五个浏览器工具，qPCR 继续使用独立的项目与运行历史。

数据库默认位置为 `%LOCALAPPDATA%/bioeng-qpcr/workbench.sqlite3`，程序端口变化
不会改变记录位置。原始文件随记录保存在本机数据库中，备份时需要包含该数据库。

历史列表展示每个模块最近 100 条，不删除更早的记录。JSON 备份导入上限为 64 MiB；
更大的归档应备份数据库。未执行分析的草稿仅保留在当前页面内存中。

本版不改变科学计算公式。多内参工作流、酶全局拟合界面、批量审阅与新实验模块
仍属于后续阶段。

恢复项目时直接提交 JSON 备份原文，避免浏览器重写小数表示导致快照校验失败。
